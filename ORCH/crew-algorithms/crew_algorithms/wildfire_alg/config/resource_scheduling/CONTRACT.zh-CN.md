# 任务契约与证据等级

主实验采用 `create_level_presets(profile, family="focused")`，12个配置仅在0或8步增加一处火点，采用灭火游戏类型3；资源数1/2严格配对。`family="combined"`保留原12个火点+平民扩展任务。每个family有无期限、urgent、relaxed三档，共72个可加载配置变体。`audit.py`静态检查两组24个配置。

完成定义按截止时刻的after_action状态评估，deadline=实际点燃确认步+预算。现配置里的事件timestep只表示提交计划，公告不是物理生效证据。未点燃、新区域没有活火、原火已灭或worker已全损失时，先标记操纵无效/不可判定，不计作调度失败。

| 目标 | 足以判完成的证据 | 现有快照是否足够 |
|---|---|---|
| 新火点点燃 | 新区域火格从无到有；保留地图坐标和时间 | 否；公告及全局fire_active不足以归因 |
| 无人机核实 | 指定无人机在释放后直接观测到新区域活火格，带观测时间 | 否；共享累计地图不含原始观察者与刷新时间 |
| 直升机部署 | 两名消防员先进入该直升机载荷，再在新火区安全区下客；记录身份、位置和时间 | 部分；载荷总数/位置可见，身份链缺失 |
| 推土机施工 | 释放前固定短线段及含树目标格，记录该推土机在期限内清理的格数 | 否；全局trees_cut不能归因地点或worker |
| 原火目标 | 截止前原火区无活火；新火区另计 | 否；原生fire_active只给全局状态 |
| 组合救援目标 | 初始与新增平民各自送达目标数 | 否；全局civilians_rescued不能区分来源 |

审计器遇到缺少这些证据时输出unknown，不将全局奖励当作子任务成功。用于正式评分前，需要在Unity返回世界快照或事件记录里补齐逐区域火格、逐worker直接观察、载客身份/上下客、目标格施工归因。补齐后以首次完成步和期限比较，超时仍记录完成步。

“资源竞争”也需单独验证：释放时两个未完成目标均有相关工作；1-worker组的同类工作在期限内有重叠需求；2-worker组存在可执行的并行分配。只按人数差异命名Contended不足以证明实际竞争。应用脚本调度分别验证保持分工与立即重分配；前者错过新期限、后者两个目标都完成，才归为可调和抢占实例。
