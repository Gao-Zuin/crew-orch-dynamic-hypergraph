# 轨迹对照与难度修订

## 已有证据

- research/dynamic_followup/seed137_full_review.md：旧第二火点在18步触发，19步分组，8号到24步才向新目标推进，27步到(66,69)，28步损失；新火点两名执行者均没有喷水。原始 behavior_summary.json 也确认100步失败、7损失、灭火17。响应成本不只是重组一轮，还包含约5步决策滞后与至少3步移动。
- seed256_full_review.md：19步建立第二火点边，23步边已退役，36步全员离线。不是把现有18步事件再压缩几步就能构成良好调度实验。
- SINGLE_RESCUE_VALIDATION_20261026_RESULT.md：9步新增平民，41步累计送达10人，60步送达14/15；没有结构变化，组内调整已能改变执行目标。该轨迹有原生异常，不能当成无故障的速度上界。
- benchmark_runs/DIVERSE_TASK_ANALYSIS.md：树线任务前3步大多在赶路，第四步才出现目标清理增量；全体先侦察再取水会增加往返。仅5步短轨迹不支持估计完整工期。

这些证据主要来自旧 HT/ORCH 物理执行与少量官方 ORCH 短轨迹，并非本任务集、相同地图、相同worker的成功基线。下面数值是待校准候选，不是已证明可解的阈值。

## 修订

Late 事件由12/13步提前到8/9步，以增加严重减员前处理新目标的机会；代价是初始协作可能尚未稳定，必须检查 release 时已有持续执行的原目标。Early 保留0/1步，属于开局竞争对照，不能解释为已建立组织后的重组。

原竞争窗口截止40步改为 release+13，即约12步候选重叠段；窗口只是分析标注，实际竞争结束必须取第二需求完成/释放资源时刻。新增目标改成可释放专家的局部动作：无人机新区域直接可见火格、直升机向新区域实际部署至少2名消防员、推土机清理短线段。避免要求一台机器同时永久驻守两地。直升机不能运输平民，已纠正原配置。精确公告坐标削弱了“搜索”必要性，无人机现在评估直接核实；也可能被其他worker替代，应如实记录替代成功。

提供 relaxed=24步、urgent=16步两档新增目标预算，原目标预算100步。调用 create_level_presets('urgent') 或 ('relaxed') 可将要求放进原任务描述与事件公告；无参数保留无截止时间对照。两个版本事件、资源相同，便于比较截止时间效应。16步超过旧seed137观测到的约8步重组/出发/移动成本，但未含任务操作、补水与安全余量，不能据此证明足够。不同worker最终应采用不同校准预算。

当前只有公告与实验契约，没有更改全局runner。必须额外按身份、位置和新目标区域评分；全局灭火数/运输数无法归因新任务。Full_Game原生成功规则只检查全局火灭，不要求救援全完成；评估组合任务时需独立检查救援目标，不能直接使用原success代表全部完成。已有runner也可能在未来事件前提前成功，须标记为事件未执行，而非有效动态实验。

## 冻结前的可解性判据

1. 对每个种子保存 release 前原任务进度、存活、位置、水量、载荷；确认事件物理生效且原任务未完。
2. 依据实际地图选择安全卸载区和有树的短线段，并固定到该种子的评估清单。火点无可燃物、线段无树、路线不可达时判无效操纵，不能算策略失败。
3. 同一状态比较保持原分工与立即调配的脚本基线，包含移动、取水、上下客和返程。调配基线能完成两个目标，且保持分工在新截止时间前失败，才说明期限产生可解调度压力。
4. 用至少5个种子的实际工期校准：新任务预算 >= 调配基线工期+安全余量；同时 < 保持原结构等待后的工期。若不存在该区间，改位置、任务量或资源数，不继续缩短期限。
5. 区分双方可完成、仅能保新目标、两者都不可完成。主实验采用双方可完成；必须牺牲目标的不可调和条件单列优先级决策实验。
6. 原任务截至100步而新任务截至release+16/24，要求先释放再返回，不要求专家持续两地同时在场。观察实际目标转移、资源释放和原目标恢复；结构变化并非逻辑必然，组内重派也可能成功，不应以“没有改图”单独判失败。
