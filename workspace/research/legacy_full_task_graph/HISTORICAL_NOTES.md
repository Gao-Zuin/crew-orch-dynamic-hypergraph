# CREW-Wildfire 任务阶段超图：实现与验证进度

独立模式 `HT`，不再调用 SpatialPolicy，不与旧 P/HA/HR 实验混算。

## 实现目标

超边是子阶段的协作单位，包含目标、任务依据、成员、leader、成员职责、当前 context、未完成责任、规则、完成检查和通信策略。形成和变化由 LLM 提案，另一份独立上下文的 LLM 审查任务适配与检查覆盖，代码核验结构及可观测谓词。

## 已实现

- 任务驱动组织：输入整体任务、各成员能力/位置/资源、仓库原有任务知识与动作能力、既有超边、已送达消息和历史交接；不是按位置自动分三人组。
- LLM 定义成员、leader、职责、目标、规则、上下文及逐项完成条件。每轮检查每条旧超边，判断继续、修订、阻塞、完成或中止。
- 阶段生命周期：旧超边退役、后继超边形成、context 与未完成责任交接；退役记录保留。正在执行的超边可以修订成员、leader 和任务，修订增加版本。
- 重叠成员：同一 agent 可属于多条超边，读取多边上下文；每步恰有一个物理执行归属，其他身份用于协调，避免两个相冲突的动作同时提交。
- 超边内支持全互通或 leader-star；边间支持有向 leader 联系或明确指定的共同成员中继。所有消息按源边/目标边执行权限检查，GLOBAL 只在边内广播。
- LLM 的逐项检查必须引用现有证据；数值资源/任务计分/位置及 all/any 量词结果与真实快照对照。未知不能当完成。独立 LLM 审查目标覆盖、容量可行性、事实声明和责任保留。
- 组织提案整体校验通过才提交。无合法提案时暂停动作，不退回原始广播或空间分组。
- 每个动作带执行超边与版本；改派时撤销旧任务权威、清理旧无标签聊天，原记录保留在日志中。底层执行仍使用 CREW 原动作接口。
- 末步动作后仍进行一次 LLM 组织检查；组织层全部调用计入用量。

## 代码

- `coordination/task_hypergraph.py`：组织状态、原子提交、生命周期、责任交接、权限和事实谓词。
- `coordination/task_policy.py`：组织 LLM 与独立上下文的审查 LLM；记录请求、原始返回、拒绝原因及用量。
- `coordination/task_runtime.py`：真实观察接入、任务下发、通信投递、动作归属与阻塞。
- `scripts/run_task_hypergraph.sh`：独立运行入口。
- `scripts/run_task_hypergraph_smoke.py`：冻结源码、限时运行和保留开发检查结果。

模式复用 Embodied 的感知、LLM 动作选择与 Unity 接口，不复用它的无约束广播组织。`RuntimeBridge.from_environment` 仅在 `CREW_HYPERGRAPH_ARM=HT` 时选择新架构，其余模式保持原路径。

## 验证状态

46 项新离线测试通过，覆盖任务建边、等待依赖、重叠执行、跨边路由、阶段退役/交接、逐项检查、历史证据与当前数值证据、失效 leader、事件持续责任、空链路拒绝、精确检查不得声称未建模的“或”、提案修复和独立审查。另有 40 项原超图/实验工具测试通过。真实运行的动作、消息、版本、审查、用量由 `scripts/audit_task_hypergraph.py` 从事件流重放；审计通过不代表语义检查或任务完成。

真实运输开发检查 `benchmark_runs/task_hypergraph_pilot_v4`：7 人、12 步，4 次图提交，9 个获授权动作，75 个暂停动作，审计通过；第一批 5 人登机，直升机最终到达目标，但未执行卸载，已运送人数仍为 0，任务未完成。图中第一批和第二批运输是依赖关系，直升机跨两边重叠；没有真实跨边投递，也没有完成后的阶段退役。v1–v3 记录保留，用于追踪容量知识、API 代理和等待依赖的修复历程。

真实无人机失联检查 `benchmark_runs/task_hypergraph_drone_lost_v2`：3 人、8 步，预设第 4 步失去 1 号无人机；该损失在世界快照中证实，组织器退役旧边、建立 2/3 号成员新边并交接未完成责任。17 个动作获授权，4 个暂停，审计通过，未达到双人同时看到火的完成条件。`task_hypergraph_drone_lost_v4`：3 人、7 步，旧边在失联后原 ID 修订、leader 从 1 改为 2，17 个获授权动作、2 个暂停；末步同时见火人数为 1。`task_hypergraph_drone_lost_v5`：3 人、6 步，失联事件被明确确认并下发给存活成员，7 次图提交、17 个获授权动作、0 个暂停动作；仍未完成任务。两种合法重组形式都已在 Unity 执行：后继边交接，或原边成员/leader 修订。

上述失联任务的火会蔓延，`trees_burned` 也随时间增加；它验证了成员消失后的重组，没有证明新火点迫使旧路线改变。官方 `Suppress_Fire_Extinguish_Second_Fire` 在第 18 步于 (70,70) 生成第二处火。`benchmark_runs/task_hypergraph_second_fire_v2`：8 人、20 步，第二火点公告进入组织器后，模型仍反复只处理原火点，组织器未提交新方案，全队停工；任务失败、审计通过。这是环境变化下组织失活的真实证据，不是旧路线继续执行导致的损毁证据。

为了把事件提前到可快速观察的边界，同一预设、同一种子另设诊断性时程：第 4 步注入第二火点，**不与官方 benchmark 成绩混算**。`task_hypergraph_second_fire_early_v2` 仍在事件后拒绝全部新提案；`task_hypergraph_second_fire_early_v3` 在事件后提交双超边：1 号属于新旧两边、物理执行归新火点，2–8 号继续负责原火点。事件后 8 个动作确实分别由两边授权；1 号先向水源补水，没有到达新火点。下一轮独立审查误把允许的重叠成员当冲突，造成 8 个动作暂停。该次链接方向也使跨边投递无法到达不同的接收者。整轮 6 次图提交、48 个获授权动作、8 个暂停动作、0 次跨边消息，审计通过，任务失败，最终全局 `fire_active=true`。调用量 216 次、输入 1,173,539 token、输出 65,945 token；这包含全部 8 个执行 agent 的推理，不能当作只组织超图的成本。

根据这份轨迹，后续版本增加持续火点的当前负责人约束和“跨边链接必须有不同接收者”约束；这两项均有离线回归测试。第 6 步真实快照的**控制层重放** `task_hypergraph_second_fire_early_v3_t6_replay_v1` 在 2 次模型调用后得到合法方案：2 号执行新火点，其他成员继续原火点，1 号作桥接；没有向 Unity 提交物理动作。对通过硬约束的持续火情方案，审查器否决可在严格条件下记录为告警：旧边不宣称完成，或其完成检查全是当前快照已满足的精确检查；未完责任必须交接。依赖语义判断的完成宣称仍不能绕过审查。

`task_hypergraph_second_fire_early_v4`：8 人、7 步，事件后反复给出非法桥接、原地改阶段名或覆盖不足的“完成”宣称，最终没有事件后的图提交；40 个获授权动作、16 个暂停，任务失败、审计通过。第 5 步快照的控制层重放 `task_hypergraph_second_fire_early_v4_t5_replay_v1` 得到双后继边，但不作为真实动作证据。

`task_hypergraph_second_fire_early_v5`：同一诊断任务/种子/步数，事件后的真实图在事件 453 将旧 `E1_water_and_stage` 以 `revise` 退役并交接到 `E1_original_fire_stage`，同时建立 `E2_second_fire_response`。成员 1–4 和 5–8 分别对原火点、新火点执行，1/5 两位 leader 间有双向有向链路，并在事件 467、478、547、555 产生四次真实跨边投递。第 6 步两边继续执行。整轮 7 次图提交、1 次交接、56 个获授权动作、0 个暂停，审计通过；最终 `fire_active=true`、任务未完成。调用量 244 次、输入 1,057,063 token、输出 79,077 token，包含所有 agent 的感知、通信、行动和组织推理。

v5 暴露的检查失真：描述写“靠近水源**或**已向火点前进”，精确谓词却只能判定靠近水源；成员正常离开水源后检查变成未满足。当前代码拒绝精确检查描述中未建模的“或”，并提示将位置条件改到当前阶段目标处，或使用证据不足时保持 unknown 的语义检查。`task_hypergraph_second_fire_early_v5_t6_replay_v1` 在真实第 6 步快照上经 3 次模型调用，将两条边改为指向各自火点的后继边与位置检查；这是控制层重放，尚无新版本 Unity 动作验证。

已经取得的真实机制证据：任务驱动建边、事件后阶段重组与责任交接、两处火点并行执行、双向跨边实际投递、后续轮次持续执行。仍未取得第二火点的有效压制或运输任务完成后的阶段交接。当前结果不能推出超图提高任务成功率或防止火场损毁。事件控制只在动作边界重规划；执行步内不能撤销已提交给 Unity 的动作。

## 运行

```bash
LEVEL=Transport_Firefighters_small SEED=283 MAX_STEPS=5 \
RUN_LOG_ROOT=/data/gzy/selfevolve/CREW/benchmark_runs/task_hypergraph_new_run \
bash /data/gzy/selfevolve/CREW/scripts/run_task_hypergraph.sh
```

指定输出目录必须不存在；不覆盖、不自动重复已有运行。API 密钥继续由已有 runner 读取，不写入报告或源码归档。

## 边界

目前任务规则是 LLM 定义的文字约束，可观测完成条件可精确核验，但没有宣称所有自然语言安全规则均已形式化。地图仍来自环境共享累积缓存，无法伪装为当前直接可见火场。执行步内不可撤销已经发给 Unity 的动作，只能在下一动作边界依据最新快照撤销旧任务、重新组织。

目标保持为完整任务驱动超图架构；真实执行和动态变化验证未完成前，不标记整个目标完成。
