# 专家能力原子与共享边的语义

组织器现在收到两层静态描述：每个在线worker的能力原子键，以及只出现一次的能力目录。消防员的逐树砍伐、喷水、空箱补水、救平民，推土机的行进中清理，无人机的飞行侦察，直升机的运消防员/向下投水/补水分别表示。目录来自 `coordination/ability_atoms.py`，并不暴露worker实时位置、水量或载客信息；这些仍须通过worker报告得到。

多条边共享同一专家，表示协作关系和消息可达；worker仍只有一条active执行归属、每步只能执行一个物理动作，水量和载客能力不会复制。一个无人机同时属于原火区队伍和新火区队伍时，两个leader都能与它沟通，但必须排定巡查顺序。组织器prompt也在无坐标火警条件下明确要求从worker报告取得位置，不能从事件ID或静态任务设计推断。

这个能力目录服务于语义规划，并未实现强制的资源预约、互斥锁或完成评分。后续可比较三种方案：固定边下通过leader中继共享专家、可变边下让专家加入两个任务边、可变边下新建一支混合队伍。收益指标应同时计入消息时延、专家往返、原目标暂停时间和新目标处理结果，不能只数边数。
