# 固定分组阶段失配：探索性实验预登记

状态：**已暂停，不能用于原完整任务阶段超图的效果结论。** 本文件针对后来接入的轻量 `SoftTaskGraph`，不是原有 `TaskHypergraph` + `LLMTaskPolicy` 的固定组织消融。任务、seed 和指标可作草案参考；在完整超图上重新定义固定组织约束和组合场景前，不启动所述 18 次正式运行。

## 任务、运行和可比性

- 环境：CREW/ORCH 的 Unity Wildfire，`HT` 软任务超图，DeepSeek `deepseek-chat`，temperature 0，现有 Embodied 动作、一次通信轮及记忆清理规则。固定 `CREW_HT_FIXED_GROUPS=1`。
- 两个现有综合任务：`Rescue_Civilians_Search_Rescue_Transport`（14 人，原时域 60 步）和 `Full_Game`（15 人，原时域 120 步）。三个预定环境种子分别为 42、137、256。每个任务种子只做一次完整固定分组运行，共 6 次；失败、超时也保留。
- 每次在任务起点形成一次组织。后续可更新目标、成员工作建议和协调建议；组 ID、成员、leader、执行归属保持不变。成员死亡只允许删除死亡成员、必要时从存活原成员中接替 leader，并单独记为人员损失。若模型提议改变分组，记录拒绝和保留旧组织。
- `Full_Game` 原 validator 主要看灭火，不能当作所有目标完成。按世界计数逐项报告，最终成功另保留原 validator 输出。

## 阶段与卡点

先看动作后世界快照。救援任务的阶段变化定义为首次 `civilians_scouted>0` 或 `civilians_rescued>0`；Full_Game 定义为首次 `fire_scouted>0`、`civilians_scouted>0`、`civilians_rescued>0`、`fire_extinguished>0` 中任一项。该定义只定位新事实/目标出现，不能单独证明组织失配。

有效进展用动作后世界状态的累计计数增加判定。救援看 `civilians_scouted`、`civilians_rescued`；Full_Game 看 `civilians_scouted`、`civilians_rescued`、`fire_extinguished`、`correct_trees_cut`、`firefighters_transported`。`fire_scouted` 是同时见火人数，单独用于阶段提示，不当作累计进展。连续 **3 个完整决策轮**上述计数无增加，且任务仍有未完成目标，才进入人工核查。正常搜索、必要前置等待和连续导航都不能单靠此规则判为失配。

核查只使用该时刻已记录的世界快照、成员资源和位置、已送达消息、实际动作与结果。分别记录：事实首次出现与送达/使用时刻；可用资源持有者、容量和可交付路径；旧目标是否已达成及多余动作；争用动作和环境后果。每个卡点必须给出「谁知道什么、谁能行动、实际为何未推进」的事件 ID 链。仅有 agent 自述不合格。

在六条完整轨迹中，每条只取阶段变化后**首次**符合停滞和可核实失配证据的位置作为候选。优先选来自不同任务的两个候选；若只有一个任务有候选，选最早出现的两个。若少于两个，报告不足，不放宽标准补足数量。人工诊断记录候选、被排除理由及证据链，先于续跑冻结。

## 一次成员调整与对照

原组织分支沿用同一初始组；干预分支只改变已有组的成员和执行归属。组 ID、组数、每组规模、leader、目标、建议、消息规则、预算和已有聊天历史不变；被移出组的旧个人任务提示从该组删除，不新增提示或计划。每个卡点两分支各 3 次短续跑，剩余预算一致。重组文件只从卡点时系统已经获得的信息撰写，登记为人工诊断干预，并附上变动前后成员表及理由。

Unity 当前没有可恢复环境+库存+agent 历史+通信队列的检查点。本批使用同种子重新开局、重放基线初始组，并在预先登记的卡点步尝试干预。每次同时比较到卡点时的世界计数、agent 位置/资源、已送达消息与组状态；若前缀明显分叉，把续跑标为 **非同状态近似比较**，只作描述，不写成同一卡点的因果对照。模型 temperature 0 也不能保证远端调用完全确定。

## 结果与图

- 有效进展：卡点后相同剩余预算内，上述预定累计计数各新增多少；另列最终原 validator 结果与综合任务各目标状态。
- 恢复时间：从卡点到首次有任一预定累计计数增加的环境步数；没有增加记超时。
- 成本：输入/输出 token、API 次数和墙钟时间；从重跑起点及卡点后分别报告，人工重组本身零模型调用，若后续常规组织调用增加则计入。
- 时间线：每个 agent 每步的当前目标/组、动作、行动后资源变化、等待/失败标记，画出干预时刻。消息另附发送者、接收者、送达事件 ID。
